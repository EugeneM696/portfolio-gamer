- **Сторінка застосунку:** `api.html` (скрипт `api.js`, стилі `api.css`)

### Картка використаного API
- **Назва сервісу:** PokéAPI
- **Базова адреса (Base URL):** `[https://pokeapi.co/api/v2/pokemon/pikachu]`
- **Приклад повного запиту:** `[https://pokeapi.co/api/v2/pokemon?limit=6&offset=0]`
- **Ключові поля JSON-відповіді:** `[id, name, height, weight, sprites.front_default, type]`
- **Як сервіс повідомляє про порожній результат (`empty`):** `[для неіснуючого імені повертає статус 404 Not Found і текстовий рядок "Not Found"]`
- **Чому `fetch()` не відхиляє `Promise` при статусі `404` або `500`:** Оскільки сервер прийняв запит і надіслав коректну HTTP-відповідь, на мережевому рівні обмін відбувся успішно. Для перевірки успішності статусу (`200–299`) необхідно вручну перевіряти властивість `response.ok` і викидати помилку через `throw`.

Відповіді на ключові запитання
Чому прапорець у цій версії не перемикається візуально, хоча onToggle викликається? Оскільки атрибут checked={todo.done} прив'язаний до масиву констант initialTodos, а реактивного стану (useState) у застосунку ще немає, дані залишаються незмінними і React не запускає повторний рендеринг із новим значенням.

Навіщо потрібен атрибут key у списках? Атрибут key дає кожному елементу списку стабільну унікальну ідентифікацію (todo.id), щоб під час оновлення даних React міг точно визначити змінений, доданий чи видалений елемент і не перемальовував увесь список.

Що стало простішим порівняно з версією на «чистому» JavaScript (ЛР № 7)? Інтерфейс став декларативним і розділеним на невеликі незалежні модулі-компоненти: більше не потрібно вручну викликати document.createElement, append і синхронізувати кожен DOM-вузол — достатньо описати розмітку JSX як функцію від вхідних даних props.

## Лабораторна робота № 10: React — стан, хуки та форми

**Підпроєкт:** `todo-react/` (запуск: `cd todo-react`, `npm install`, `npm run dev`)
**Варіант №:** 12 (`portfolio-gamer` — Список ігор для проходження та стрімів)
**Параметри варіанта:** `USER_ID = 2`, `LIMIT = 10`, `INITIAL_FILTER = 'all'`, `MIN_QUERY = 2`, ключ сховища `todos-lr10-12`

**Реалізована функціональність:**
* керування станом списку, фільтрів та пошуку за допомогою хука `useState` (з дотриманням імутабельності);
* контрольована форма `TodoForm` із валідацією мінімальної довжини назви;
* завантаження початкових даних із REST API (`JSONPlaceholder`) через `useEffect` із підтримкою скасування запиту (`AbortController`) та станів `loading`, `error`, `success`;
* обчислення видимого списку `visibleTodos` та лічильника `doneCount` як похідних даних;
* автоматичне збереження та ліниве відновлення стану з `localStorage`.
